Why They Return
Created by team

on

0

Gemma
HuggingFace Hub
Problem: about one in four online clothing orders comes back, and size and fit is the top reason (Coresight Research, 2023). The reasons are already in the reviews, but nobody reads 300 reviews per product.

User: fashion sellers and rental shops who need to know which items to fix first and what to change on the listing.

What it does: Gemma 3 12B runs on an AMD Radeon PRO W7900D with ROCm and PyTorch. Pass one reads every review and returns the fit direction (runs small, runs large, true to size), other causes (length, fabric, colour vs photo, comfort, zipper), the exact customer quote and a one-line fix. Code counts the shares per product. Pass two sees only those counts and quotes and writes the size note, the description sentence and the photo to add. The seller gets items ranked by fit-return risk, a report per item, copy-ready text and a money estimate. A live notebook runs it on the AMD GPU: 30 reviews of a new item in 27.8 s.

Proof: Rent the Runway renters label every review fit, small or large. We hid the label and compared with the keyword rules a seller would write. 900 reviews: macro-F1 0.737 vs 0.606; Gemma finds 64% of "runs large" reviews, rules 40%. 40 products drawn after the prompt was fixed, run once: Gemma ranks items that run large at Spearman 0.87 vs 0.72; on items that run small rules are level (0.84 vs 0.88). The README shows the full history, including a prompt that over-counted and how it was fixed.

Why AMD and open weights: one 48 GB Radeon card holds the model in bf16 and the customer text never leaves the seller's GPU. Next: vLLM on AMD Instinct, Shopify imports, A/B test of the size note against return rate.

WebRetriever — Deterministic Web Retrieval Agent
WebRetriever is an autonomous web information retrieval agent built for AMD AI League Match 4: Intelligent Web Information Retrieval. Ask in plain English and get back the specific information you asked for, with the exact source URLs behind it — or an honest refusal when no verifiable answer exists.

How it works — five-stage pipeline with a deterministic core:

Understand — parses the request into intent (price, contact, hours, spec, definition, how-to, date, fact), entities, and 2–4 search query variants. No ML model required.

Search — provider chain with automatic fallback: TinyFish Search for the best quality (JS-aware), and DuckDuckGo HTML as the keyless fallback with no signup needed.

Fetch + navigate — fetches top hits, then follows promising in-page links within a fixed budget (8 pages, 2 hops) when the answer looks like it is one click deeper.

Extract — structure-aware parsing: JSON-LD (Product, Organization, FAQPage), HTML tables such as spec sheets, intent-specific patterns for prices, phone numbers, emails, hours and dates, plus ranked text spans.

Verify — every candidate is checked against its own source text; independent multi-source agreement boosts confidence. If nothing is supported by evidence, the agent refuses instead of guessing.

The core pipeline uses no LLM, so results are reproducible and cheap. Citations are mandatory, and the agent runs on the free tier with no paid APIs. MIT licensed and Docker-ready, with 12 unit tests.

WebScout ROCm
WebScout is an advanced, high-efficiency autonomous web information retrieval engine built specifically to harness the massive parallel processing power of AMD ROCm hardware. Designed for modern AI agents and knowledge workers, WebScout delivers lightning-fast web scraping, DOM parsing, and vector embedding generation. By leveraging AMD ROCm and ROCm-accelerated local LLMs, WebScout processes millions of web tokens with minimal latency, ensuring robust data extraction, semantic search, and structured knowledge synthesis. Key features include intelligent adaptive rate limiting, automated anti-bot avoidance strategies, robust proxy rotation, DOM distillation to remove boilerplate clutter, and real-time vector embedding indexing directly on AMD Radeon and Instinct GPUs using PyTorch and ROCm hipBLAS. WebScout empowers autonomous agents to query live web data securely, efficiently, and at scale without relying on expensive commercial APIs.

Kaminari Web Retrieval Agent
An autonomous web retrieval agent built for AMD AI League Match 4: Intelligent Web Information Retrieval. The agent accepts natural-language requests (for example: "find the current lead time for part X on the supplier site") and returns the exact information together with its source URL. Pipeline: (1) query understanding and target-site selection, (2) deterministic navigation with retries and fallbacks, (3) structure-aware content extraction, (4) evidence-grounded answer synthesis with citations, and (5) refusal when a fact cannot be verified against a primary source. A resident local model on AMD ROCm handles extraction and reranking so per-request latency stays within the evaluation budget. The verifier cross-checks every extracted value against the page it came from, and every answer carries the exact source link. Built solo by Eran Rosadi (Kaminari Research).
